## 0. 使用说明

本清单覆盖三个层次的设计质量验证：

| 层次 | 执行者 | 时机 | 说明 |
|------|--------|------|------|
| **L1 设计自检** | 设计师 | 设计交付前 | 文档内部一致性、状态覆盖率、术语规范 |
| **L2 设计走查** | 设计师 + 前端 | 实现完成后 | 视觉还原度、动效参数、材质实现 |
| **L3 交互验收** | QA + 设计师 | 功能测试阶段 | 交互流程完整性、边界场景、可访问性 |

### 检查结果标记

```
✅ PASS — 通过
⚠️ MINOR — 小问题，不阻塞发布但需记录
❌ FAIL — 阻塞发布，必须修复
— N/A — 不适用
```

### 2.2 材质与透明度（重点）

> ⚠️ 警告：这是最容易出错的环节。CSS `backdrop-filter` 在 WebView2 中不能模糊桌面。参考 [附录 C](design-system.md#附录-ctauri-webview2-渲染约束与浏览器差异)。

| # | 检查项 | 正确实现 | 常见错误 | 结果 |
|---|--------|---------|---------|------|
| 2.2.1 | 主控制面板背景 | Rust `window.set_mica(true)` | ❌ CSS `backdrop-filter: blur()` — 无法模糊桌面 | |
| 2.2.2 | 右键菜单背景 | Rust `window.set_acrylic(true)` 或原生菜单 | ❌ CSS 半透明背景 — 看不到桌面内容穿透 | |
| 2.2.3 | 悬停控制条背景 | Rust Acrylic + CSS 半透明回退 | ❌ CSS-only blur | |
| 2.2.4 | Toast 背景 | Rust Acrylic (80%) | ❌ 纯 CSS 背景不透桌面 | |
| 2.2.5 | 宠物展示区 | Tauri window `transparent: true` + Three.js `alpha: true` | ❌ 窗口不透明，宠物背后有实色背景 | |
| 2.2.6 | 非宠物区域点击穿透 | Rust `WS_EX_TRANSPARENT` + hit-test | ❌ 整个窗口阻挡点击 | |
| 2.2.7 | 宠物区域不穿透 | Rust hit-test 逻辑：宠物 bounding box 内 return HTCLIENT | ❌ 宠物区域也穿透，无法点击 | |
| 2.2.8 | 暗色模式材质跟随 | Mica/Acrylic 自动跟随 Windows 主题 | ❌ 手动设置颜色覆盖了材质效果 | |
